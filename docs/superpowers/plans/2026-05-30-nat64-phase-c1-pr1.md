# NAT64 Phase C1 — PR 1 (Controller: egress approval + ACL route synthesis) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an admin designate a peer as the tenant's NAT64 egress and have every ACL-permitted peer automatically route `<nat64_prefix>::/96` translation traffic to it — the routing scaffolding of Phase C, mirroring the shipped exit-node admin model.

**Architecture:** Mirror the exit-node mechanism exactly. Capability flows through the REST register side-channel (`peers.nat64_egress_capable`), NOT the gRPC proto — so **no proto change**. Admin approval is a `POST /api/v1/peers/{id}/nat64-egress` handler writing `peers.nat64_egress_approved`. The ACL route is synthesised in `allowedIPsFor` (the L3 enforcement path): when `tenant.dns64_enabled` is true and `dst` is the active approved egress, `<resolved nat64_prefix>::/96` is appended to dst's `AllowedIps`. The route is gated by `policy.Allow` (same as exit-node). The simulate path is NOT touched — it already only shows tunnel IPs, not subnet/exit routes.

**Tech Stack:** Go (controller), PostgreSQL.

**Spec:** `docs/design/2026-05-30-nat64-phase-c1-egress-acl.md`. **Umbrella:** `docs/design/2026-05-27-nat64-architecture.md` §5.

**Corrections to the spec (discovered during grounding):** (1) **No proto change** — exit-node capability/approval do not use the proto `Peer`/`RegisterRequest`; they use the REST register body + REST `apiPeerJSON`. C1 mirrors that. (2) Route is `POST /api/v1/peers/{id}/nat64-egress` (no `/approve` suffix — matches the exit-node route `{id}/exit-node`). (3) The simulator (`apiSimulatePolicy`/`dstTunnelIPs`) shows only tunnel IPs today (not approved-routes or exit-node `0.0.0.0/0`), so the egress route is added ONLY to the enforce path, consistent with how the other route types are absent from the simulator.

**No migration** — `peers.nat64_egress_capable`, `peers.nat64_egress_approved` exist from Phase A migration 00018; `tenants.dns64_enabled` from Phase B 00019.

**⚠️ Verification:** the repo/handlers/e2e tests touch a real Postgres and are SKIPPED by a bare `make test` (no `DATABASE_URL_TEST`). CI's "Unit + integration tests" job runs them against a Postgres service — this is where the last three NAT64 PRs' bugs surfaced. **Before pushing, run the integration suite locally against a throwaway Postgres** (Task 6 Step 3).

// apiPeerSetNAT64EgressApprovedReq is the request shape for approving/
// revoking the NAT64 translator-egress role (NAT64 Phase C1).
type apiPeerSetNAT64EgressApprovedReq struct {
	Approved bool `json:"approved"`
}

// apiPeerSetNAT64EgressApproved implements POST /api/v1/peers/{id}/nat64-egress
// (NAT64 Phase C1). Admin flips the peer's nat64_egress_approved bit.
// Approving requires nat64_egress_capable — approving a peer that didn't
// advertise the role would be misleading.
func (h *HTTPServer) apiPeerSetNAT64EgressApproved(w http.ResponseWriter, r *http.Request, authn *authnContext, tenant *repo.Tenant, idStr string) {
	if !h.requireAdmin(w, r, authn, tenant, "peer.nat64-egress.approve") {
		return
	}
	id, err := uuid.Parse(idStr)
	if err != nil {
		http.NotFound(w, r)
		return
	}
	current, err := h.peers.GetByID(r.Context(), id)
	if errors.Is(err, repo.ErrNotFound) {
		http.NotFound(w, r)
		return
	}
	if err != nil {
		writeError(w, http.StatusInternalServerError, err)
		return
	}
	if current.TenantID != tenant.ID {
		http.NotFound(w, r)
		return
	}
	var req apiPeerSetNAT64EgressApprovedReq
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		writeError(w, http.StatusBadRequest, fmt.Errorf("decode body: %w", err))
		return
	}
	if req.Approved && !current.NAT64EgressCapable {
		writeError(w, http.StatusBadRequest, errors.New("peer is not nat64-egress-capable; client must register with --advertise-nat64-egress first"))
		return
	}
	if err := h.peers.SetNAT64EgressApproved(r.Context(), id, req.Approved); err != nil {
		writeError(w, http.StatusInternalServerError, fmt.Errorf("set nat64_egress_approved: %w", err))
		return
	}
	writePeerAudit(r.Context(), h.audits, authn, tenant.ID, id, "peer.nat64-egress.approve", map[string]any{
		"hostname":              current.Hostname,
		"nat64_egress_approved": req.Approved,
	})
	writeJSON(w, http.StatusOK, map[string]any{"id": id.String(), "nat64EgressApproved": req.Approved})
}
```

// nat64EgressRoute carries the per-register NAT64 egress routing
// decision (NAT64 Phase C1): whether the tenant has DNS64 enabled (the
// master switch), the resolved /96 prefix, and the single active egress
// peer the <prefix>::/96 route points at. Zero value (enabled=false,
// egressID=uuid.Nil) emits no route.
type nat64EgressRoute struct {
	enabled  bool
	prefix   string // resolved "64:ff9b::/96" form
	egressID uuid.UUID
}

// computeNAT64EgressRoute picks the tenant's single active NAT64 egress:
// the approved egress peer with the lowest ID (UUID string order). A
// future phase (C3) replaces the deterministic pick with health-aware
// selection. Returns a zero egressID when no peer is approved or DNS64
// is off for the tenant.
func computeNAT64EgressRoute(tenant *repo.Tenant, peers []*repo.Peer) nat64EgressRoute {
	rc := nat64EgressRoute{
		enabled: tenant.DNS64Enabled,
		prefix:  nat64.ResolvePrefix(tenant.NAT64Prefix),
	}
	for _, p := range peers {
		if !p.NAT64EgressApproved {
			continue
		}
		if rc.egressID == uuid.Nil || p.ID.String() < rc.egressID.String() {
			rc.egressID = p.ID
		}
	}
	return rc
}
```

# NAT64 Phase A — PR 2 (ACL dual-emit + Web display) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a single ACL rule reach a destination peer on both IPv4 and IPv6 — emit `<v4>/32` **and** `<v6>/128` in `AllowedIPs` on both the coordinator enforcement path and the `/simulate` preview path — and surface the peer's v6 address in the Web PeerTable.

**Architecture:** PR 1 already gave every peer an `ip6` field (DB → proto → `/api/v1/peers` JSON). This PR consumes it. Two backend touch-points build `AllowedIPs`: the hot enforcement path `allowedIPsFor` (handlers package, a pure function already under test) and the admin-only `apiSimulatePolicy` handler (server package). The spec (§6) requires both stay consistent. The simulate path's tunnel-IP construction is extracted into a small pure helper `dstTunnelIPs` so it is testable without an HTTP/DB harness (the codebase's established pattern for handler logic — cf. `augmentUpgradeAvailable`). The Web side threads `ip6` through the API DTO → domain `Peer` type → a muted mono sub-line in `AddressCell`.

**Tech Stack:** Go (controller), TypeScript/React + next-intl (apps/web), Next.js 14.

**Spec:** `docs/design/2026-05-28-nat64-phase-a-overlay-ipv6.md` §6 (ACL dual emit) + §7 row 3 (Web display). **Umbrella:** `docs/design/2026-05-27-nat64-architecture.md` §4.4. **Builds on:** PR 1 (#232) — `repo.Peer.IP6`, proto `Peer.ip6`, `/api/v1/peers` `ip6`.

## Task 1: Enforcement-path dual emit (`allowedIPsFor`)

**Files:**
- Modify: `apps/controller/internal/handlers/coordinator.go` (function `allowedIPsFor`, ~line 729)
- Test: `apps/controller/internal/handlers/coordinator_enforce_test.go`

**Context:** The current `allowedIPsFor` builds `out := []string{dst.IP + suffix}` where `suffix` is `/32` (or `/128` if `dst.IP` itself parses as v6 — a defensive legacy case). With PR 1, `dst.IP` is always the v4 and `dst.IP6` is always the v6. We append the v6 tunnel `/128` immediately after the v4 entry, before approved routes. Guard on `dst.IP6 != ""` so peers with no v6 (none after migration 00018, but defensive) and the existing v6-in-`IP` tests stay unchanged.

```go
// dstTunnelIPs renders dst's tunnel addresses the same way the
// coordinator's enforcement path does (NAT64 Phase A §6): the v4 /32
// plus, when present, the deterministic IPv6 ULA /128. Keeping the two
// paths in lock-step means the simulator matrix matches what clients
// actually receive.
func dstTunnelIPs(dst *repo.Peer) []string {
	out := []string{dst.IP + dstPrefixSuffix(dst.IP)}
	if dst.IP6 != "" {
		out = append(out, dst.IP6+dstPrefixSuffix(dst.IP6))
	}
	return out
}
```
